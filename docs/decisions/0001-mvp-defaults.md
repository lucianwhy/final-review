# ADR-0001：MVP 资产生命周期、报告、导出与提醒默认决策

- 状态：已接受
- 日期：2026-09-24
- 范围：MVP 路线图与后续 M0 实施合同

## 背景

PRD 规定正式学习资产可确认、可编辑、可追溯，且删除等不可逆动作必须受控。当前
实现尚未具备这些业务对象。若在实现时临时决定删除、版本和报告语义，会导致资料
来源、历史作答和导出结果相互矛盾。本记录固定 MVP 默认行为。

## 决策

1. **课程删除**：课程删除为软删除，保留 30 天。删除预览必须按资料、考试、学习资产、
   作答记录返回影响数量；用户以一次性确认令牌再次确认后才执行。回收期内不出现在常规
   列表、不能继续写入，恢复操作应恢复原有资源关系。
2. **正式资产版本**：笔记和试卷确认后是正式资产。编辑已确认资产不原地改写，而是创建
   不可变 revision 并将其设为当前版本；历史作答永久引用启动测试时的 `quiz_revision_id`。
3. **已引用资料删除**：若资料被已确认笔记或试卷引用，默认拒绝删除。只有明确选择
   `retain_source_snapshot` 时才允许：系统在正式 revision 中保留文件名、来源类型、定位器和
   必要的来源片段快照，再删除资料的可访问原件/检索内容。
4. **报告范围与预计分数**：报告由 `course_id`、可选 `exam_id`、日期范围定义。仅当关联考试
   有完整满分和题型分值结构时计算预计分数；否则只显示掌握度、目标达成度和置信度。
5. **主观题评分**：AI 对文字简答、基础计算和证明只作学习参考，界面和导出必须带
   “仅供学习参考，以教师评分为准”。每次评分保存 rubric/评分依据、模型标识与版本、输入
   版本、反馈快照和时间；不因模型升级重写历史反馈。
6. **导出**：已确认 revision 的 Markdown 是唯一内容源。Word、PDF 与打印版均从该 Markdown
   及同一 revision 元数据派生；草稿和未确认 revision 不提供正式导出。
7. **提醒范围**：MVP 实现站内提醒。邮件提醒移至后续独立里程碑，届时再处理地址验证、
   频控、退订/偏好、投递失败和监控；PRD 已作相应范围调整。

## 理由

- 软删除和确认令牌平衡误删防护与数据保留，不会把 UI 弹窗当作唯一安全边界。
- 不可变 revision 和 Attempt 固定引用让题目后来被修订时，旧成绩、解析、来源和导出仍可解释。
- 来源快照是例外删除的证据保全机制；默认拒绝避免正式资产静默失去依据。
- 预计分数只有在完整蓝图下才有明确分母和权重；否则展示它会制造不存在的准确性。
- 保存主观题评分快照既支持用户复查，也把模型输出限定为当时的参考意见。
- 单一 Markdown 源避免三种导出格式分别渲染/修改造成内容漂移。
- 邮件涉及外部投递可靠性和用户偏好，拆出后不会阻塞站内复习闭环。

## 后果

- M0 必须先交付 revision、引用快照、确认令牌与审计数据合同，不能只添加前端二次确认。
- 需要为恢复、回收期清理和“保留来源快照后删除”定义后台任务与审计事件。
- 现有 `fast_quiz_session` 和 Attempt 需作为 legacy 记录保留，不能假装已拥有 revision 外键。
- 报告 API 必须将“未计算预计分数”的原因作为结构化字段返回，而非以 `0` 代替。
- 邮件相关接口、队列、供应商依赖不进入 MVP 代码路径。
