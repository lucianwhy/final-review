# 课程对话上下文与资料访问

确认日期：2026-10-03。本文记录本次用户确认的行为及对应实现。

## 已确认行为

1. 使用统一的复习助手交流方式，每轮自动获得课程名称、学科和最新资料状态。
2. 默认访问当前课程全部可用资料；明确指定文件或章节后限定范围，不跨课程读取。
3. 资料概况返回真实文件数、可检索文件数、字数、片段数和处理状态。
4. 支持普通问答、分析讨论和学习建议；明确请求才进入笔记或出题流程。
5. 确实无法判断讨论与生成意图时针对性追问，并在同一对话内承接回复。
6. 可使用通用知识，但须区别于课程资料；“只依据资料”时依据不足就说明不足。
7. 引用实际读取到的资料，显示文件名和可用位置，支持点击查看及刷新恢复。
8. 每个新对话都知道当前课程和最新资料；聊天历史及临时范围独立。
9. 随机出题兼顾文件与知识点覆盖，保留题源取材优先级，不用重复题凑数。
10. 资料冲突时说明各自来源；用户指定依据时遵守指定，未指定时不擅自判定正确性。

## 实现与数据

- `course_chat.py`：课程上下文、统计、文件范围校验、章节正文截取、有限读取、随机取材和引用编号校验。
- `api.py`：所选模型规划本轮意图；服务器执行读取后再生成回答；课程概况由真实存储直接回答。
- `rag.py` / `postgres.py` / `storage.py`：指定文件先过滤再排序；正文章节先截取再检索，避免其他资料占据候选位置。
- `agent.py`：笔记生成遵守对话已限定的章节范围。
- `ChatHome.tsx` / `ChatSources.tsx`：聊天引用及练习题展示、来源跳转、答案按需展开、历史恢复。
- `llm.py`：DeepSeek 官方接口的结构化流程关闭与强制工具选择不兼容的思考模式。

范围状态保存于既有 conversation JSON 中的 `chat_scope`，待澄清状态保存于
`pending_clarification`；消息保存 `model`、`citations` 或 `quiz`。沿用现有存储，
不需要新增数据库迁移。上传、删除或重命名后，下轮重新读取课程与资料信息。

字数指可检索文件清洗文本的非空白字符数；片段重叠不重复累加到字数。
同一文件重复上传形成独立资料记录，因此文件数与字数按实际记录统计。

## 调用路径

`POST /api/chat/dispatch` 当前返回 `kind=chat|note`（客户端继续兼容历史 quiz 题卡）：

- chat：`reply`、`model` 和真实的 `citations`。
- note：沿用笔记配置与后台任务流程；指定资料不超过已有五份限制时预填选择。
- 模型判断为 quiz：返回 `kind=chat`、`intent=quiz`、`status=needs_input` 和
  `quiz_configuration`，前端据此打开与笔记同主题的试题配置弹窗。所有聊天出题请求均先确认，
  包括自然语言已给齐参数的请求。结构化确认成功后返回 configured，当前 M3-01 只保存配置。
  刷新通过 messages 的 pending_quiz 恢复；取消接口清除待确认配置。详见
  [试卷配置合同](quiz-generation-contract.md)。

`GET /api/courses/{course_id}/chat-quizzes/{session_id}` 继续读取历史练习题与来源；
用户点击查看答案后使用 `include_answers=true` 读取答案与解析。
资料来源跳转复用现有资料片段预览器。

问候和闲聊无需检索，课程概念分析默认先检索。
意图模型收到的是当前问题与历史的 JSON 数据，不继续扮演旧聊天中的回答者。
模型输出经过 Schema 校验；生成的引用编号必须指向本次读取的资料。

## 边界

- 单轮直接资料读取预算为 60,000 字符，随机取材预算为 24,000 字符；超过预算时明确说明部分覆盖。
- 独立快速练习接口沿用每次 1～10 题的限制；聊天试题配置最多 36 题、100 份资料；
  笔记配置沿用每次最多五份资料的限制。
- 资料未就绪、已删除或超出范围时明确返回原因，不默默扩大读取范围。
- 字段校验能确认引用位置真实；生成内容的语义正确性仍需结合原文核对。
- 本次不增加跨对话记忆或每门课单独的风格设置。
